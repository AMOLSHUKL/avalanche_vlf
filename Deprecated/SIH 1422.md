## The key redesign

The previous concept is directionally correct, but the **sensor-fusion layer should be substantially more sophisticated**.

The system should **not** say:

> “GPR = 0.9, RF = 0.85, thermal = 0.6, therefore confidence = 92%.”

That is easy for a judge to attack because those numbers are arbitrary and different sensors are correlated, conditional on victim equipment, and affected very differently by snow conditions.

The stronger proposition is:

> **An adaptive, time-critical evidence-fusion engine that changes the search strategy according to which human-specific signals are available and how trustworthy each signal is under the current snow/environment conditions.**

That is much closer to the way the Swiss rescue workflow actually works: electronic search first where applicable, while simultaneously using visual/auditory information; then pinpointing with a probe and excavation. The current Swiss 2026 rescue guidance explicitly treats the avalanche transceiver + probe + shovel combination as the core rapid-search equipment and emphasizes immediate companion rescue because survival falls rapidly with time. ([slf.ch][1])

Your supplied research already establishes the right overall architecture: hardware-agnostic ingestion, heterogeneous sensors, contextual data, confidence and search priority rather than a simple “victim detected” output.

# 1. First correct the core assumption: there is no universal sensor ranking

A sensor's value has **three separate dimensions**:

| Dimension                       | Question                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------- |
| **Human specificity**           | How strongly does this signal indicate an actual human rather than snow/debris? |
| **Penetration / observability** | Can it work when the victim is deeply buried?                                   |
| **Availability**                | Does the victim actually carry/produce the required signal?                     |

This produces a much better hierarchy than a single ranking.

### Recommended evidence hierarchy

| Evidence modality                 |    Human specificity |       Deep-burial usefulness | Dependency                       | Role in system                     |
| --------------------------------- | -------------------: | ---------------------------: | -------------------------------- | ---------------------------------- |
| **457 kHz avalanche transceiver** |            Very high |                         High | Victim must carry beacon         | Primary                            |
| **RECCO reflector**               |            Very high |                         High | Victim must carry reflector      | Primary/backup                     |
| **GPR life-sign detection**       |                 High |             Potentially high | Equipment + snow conditions      | Primary for uninstrumented victims |
| **Mobile-device RF localization** |            Very high |           Potentially useful | Phone powered/on + detectable    | Search-space reduction             |
| **Seismic/acoustic life signals** |        Moderate-high |           Potentially useful | Victim movement/noise conditions | Corroborating sensor               |
| **Thermal IR**                    | High when observable |          Low for deep burial | Surface/thermal conditions       | Surface/near-surface               |
| **RGB / visual**                  | High when observable | Very low for complete burial | Visibility                       | Surface triage                     |
| **Terrain / avalanche context**   |             Very low |                          N/A | Always available                 | Prior probability only             |

**Important:** this table is an engineering prioritisation, not a claim that these modalities have been experimentally validated against one common benchmark.

The Swiss system illustrates why this distinction matters. Modern Swiss avalanche rescue training tells rescuers to immediately perform a transceiver search while also looking and listening, then use probing and excavation; for victims without transceivers, the guidance shifts to likely-burial-area probing. ([slf.ch][1])

# 6. The mathematical fusion model

A good SIH-level implementation can use **log-likelihood evidence fusion**.

Let:

[
H = \text{“a human victim is present in this cell”}
]

For each sensor group (g):

[
LLR_g =
\log
\frac{P(z_g|H)}
{P(z_g|\neg H)}
]

Then:

[
\boxed{
L(H)=
L_0+
\sum_g
w_g(q_g),LLR_g
}
]

where:

* (L_0) = contextual prior from terrain / last-seen position / avalanche flow
* (z_g) = sensor evidence
* (q_g) = sensor/environment quality
* (w_g) = reliability weight determined from validation data

Finally:

[
P(H)=\frac{1}{1+e^{-L(H)}}
]

### Why this is much better

The system doesn't say:

> "GPR gets 40%, RF gets 30%."

Instead:

> **A strong human-specific signal receives more influence because the measured evidence is more discriminative.**

And the weight falls automatically if:

* sensor quality deteriorates,
* interference increases,
* snow conditions invalidate the modality,
* the signal is inconsistent over time.

# 7. Avoid double-counting correlated sensors

This is a subtle but important point that could impress judges.

Suppose:

```text
RECCO = strong
457 kHz = strong
```

You cannot blindly add both as though they were completely independent human detections.

They are both **electronic/person-associated evidence**.

Therefore create evidence groups:

```text
GROUP A
Person-specific electronic
├── 457 kHz
├── RECCO
└── mobile-device RF

GROUP B
Subsurface physical/life-sign
├── GPR
├── seismic
└── acoustic

GROUP C
Optical
├── RGB
└── thermal

GROUP D
Context
├── last-seen
├── terrain
├── avalanche flow
└── operational intelligence
```

Then combine evidence **between groups** more strongly than redundant signals within the same group.

This prevents:

> RECCO + RF + phone = fake 300% confidence.


→ deprioritise unless contextual evidence changes.

The numerical thresholds are illustrative; **your team must optimise them experimentally.**

# 21. The algorithm should optimise search effort too

You can formulate the actual rescue problem as:

[
\boxed{
\arg\max_Z
\frac{
P(\text{victim in }Z)
\times
P(\text{survival}|\text{rescue time},Z)
}{
\text{search cost}(Z)
+
\text{rescuer risk}(Z)
}
}
]

This is significantly better than merely maximising probability of detection.

A cell with:

```text
P(victim)=90%
```

may still be a bad immediate choice if:

* it is beneath an unstable slope,
* access is extremely dangerous,
* another location has an 80% probability but much faster extraction.

The decision engine should therefore optimise:

### **Probability × urgency × accessibility − rescuer risk**

This directly incorporates the disaster-management reality.

# 27. What makes this SIH-ready

The presentation example you supplied explicitly recommends that AI have **one defined job, measurable performance and a fallback**, and that the team be able to answer what happens when the model is uncertain. 

Your AI's single job should therefore be:

> **Fuse heterogeneous evidence to rank where rescuers should search next.**

Not:

> "AI detects avalanche victims."

That gives you an extremely clean evaluation framework:

| Metric                           | What to measure                               |
| -------------------------------- | --------------------------------------------- |
| **Top-1 localisation accuracy**  | Did highest-ranked cell contain victim?       |
| **Top-k recall**                 | Did victim occur within first k search zones? |
| **False-positive rate**          | How often is high-priority zone wrong?        |
| **Localisation error**           | metres from true victim                       |
| **Search-area reduction**        | % of debris removed from priority search      |
| **Time-to-first-candidate**      | seconds                                       |
| **Time-to-correct-localisation** | minutes                                       |
| **Robustness**                   | performance as sensors disappear/degrade      |
| **Calibration**                  | does 80% confidence actually mean ~80%?       |

The **search-area reduction** metric could become a particularly strong SIH metric because it directly quantifies operational benefit.

> **A time-aware, hardware-agnostic intelligence layer that integrates India's existing avalanche, terrain and rescue infrastructure with heterogeneous victim-detection signals, dynamically weights evidence according to human specificity and sensor reliability, and converts that evidence into ranked victim locations and actionable search instructions.**

### Core innovation

**Not another sensor.**

**Not another avalanche-warning system.**

**Not another dashboard.**

### The innovation is:

> **Adaptive sensor-fusion + search optimisation.**

---

# 29. The final recommended sensor doctrine

### **Minimum**

**RF/person-specific signal + GPR + geospatial/context data**

### **Recommended operational set**

**457 kHz / RECCO + GPR + UAV EO/thermal + GNSS/terrain/context**

### **Enhanced**

**+ seismic/acoustic**

### **Future**

**+ autonomous UAV sensing + distributed life-sign sensing**

This lets the project work with **what India already has**, rather than demanding a new nationwide hardware deployment.

That is also consistent with DRDO's existing direction toward multisource fusion, AI/ML avalanche systems, seismic/infrasound sensing and GPR life-signal detection. ([DRDO][4])

## The strategic thesis for the whole presentation

The presentation should ultimately tell this story:

```text
SWITZERLAND
Proved that fast, coordinated multi-stage rescue saves lives
                     ↓
INDIA
Already possesses substantial sensing, forecasting,
military, NDRF and aerial-response capability
                     ↓
CURRENT GAP
Information is distributed across systems and modalities
                     ↓
OUR SOLUTION
Adaptive evidence fusion
                     ↓
OUTPUT
"Where should rescuers search FIRST?"
                     ↓
IMPACT
Less search area
Less uncertainty
Less rescuer exposure
Faster victim localisation
```

The supplied presentation playbook itself stresses a single end-to-end journey, evidence-backed claims, a clean architecture, and a demonstrable AI fallback rather than an "AI-powered everything" pitch.  

**Confidence:** high on the architectural recommendation; moderate on exact sensor-performance ordering because there is no single, open, standardized dataset comparing all these modalities under identical Himalayan avalanche conditions. The next serious step is therefore to make the **fusion algorithm experimentally testable**, rather than asserting fixed sensor weights.
